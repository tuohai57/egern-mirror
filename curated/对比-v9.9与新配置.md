## 三、去广告：三层逐层比

### 第 1 层 DNS 拦截

| | v9.9 | 新版 |
|---|---|---|
| DNS forward 里的 reject | 只有 `httpdns.yaml`（58 条，拦 HTTPDNS 域名本身） | **`ad-full.yaml` 382,581 条全部 reject** |

差别：旧版只在 DNS 层拦"HTTPDNS 服务商"，广告域名照样解析出 IP、照样建连接、再被规则层 REJECT 掉。
新版在解析阶段就返回空，**连 TCP 握手都不发生**——更快、更省电，而且绕不过去。

### 第 2 层 规则层 REJECT

| | v9.9 用的表 | 条目 | 新版 |
|---|---|---|---|
| adrules | ✅ | 211,098 | ✅ |
| AdvertisingLite | ✅ | 37,879 | ✅ |
| ADLite | ✅ | 60,137 | ✅ |
| AdGuardSDNSFilter | ✅ | 109,050 | ✅ |
| Privacy（隐私追踪） | ✅ | 39,925 | ✅ |
| Hijacking（劫持站） | ✅ | 186 | ✅ |
| Beats（仿冒） | ✅ | 714 | ✅ |
| **AdvertisingTest** | ❌ **没用** | — | ✅ 318,626 |
| **AntiAD** | ❌ **没用** | — | ✅ 303,395 |
| **AdBlock** | ❌ **没用** | — | ✅ 77,213 |

旧版把 7 张表**分 7 个 rule_set 分别挂**，新版合成一个 `ad-full.yaml`（8 份并集）。

**覆盖实测（含后缀继承，这才是真实覆盖）：**

| | 域名数 |
|---|---|
| v9.9 广告层并集 | 290,419 |
| 新版 ad-full | **357,924** |
| **v9.9 有、新版没覆盖** | **125**（全是 IP 字面量，新版转成了 `ip_cidr`，实际仍覆盖） |
| **新版有、v9.9 没覆盖** | **78,412** |

也就是说：**旧版漏了 7.8 万个广告域名**。原因就是没挂 AdvertisingTest / AntiAD / AdBlock 这三张最大的表——它们和 adrules 重叠很多，但各有 1-2 万个独有域名。

### 第 3 层 模块改写

| | v9.9 | 新版 |
|---|---|---|
| 启用模块 | 47（**其中 4 个死链，实际 43**） | 57（全部有效） |
| 模块来源 | 大量 qingr 旧批次（2025-05 那批） | loonlab 三源合并版 + kelee 最新批次 |
| 外链依赖 | 小红书 / 微博 / 爱奇艺 / 滴滴 → `sooyaaabo/Egern`（已停更） | 全部镜像内 |

这 4 个模块实测可用（HTTP 200），只是依赖 `sooyaaabo/Egern` 这个已停更的仓库。新版换成 `loonlab` 的三源合并版，覆盖更全：
小红书 10 接口 vs 原版 7、微博 69 接口 vs 原版 28。

## 五、新版从旧版继承了什么（不重复造轮子）

这三样是旧版做得很好、我直接搬过来的：

1. **246 条手写白名单**（放在广告表之前）
   - DNS 服务器域名直连（防 DNS 循环）
   - 抖音/字节全链路直连约 30 条（防"能打开但播不动"）
   - 微信/QQ/淘宝/京东/拼多多/美团/小红书/知乎/微博/B站 整域直连
   - 腾讯视频 info4/info6/vv6/otheve.beacon、gdt.qq.com 等精准 REJECT
   - AI / 开发者 / 社交 / 新闻 关键域名
   > 这层是旧版最有价值的部分，没有它，78,412 个新增广告域名会把一堆正常功能一起误杀。

2. **221 条 MITM excludes**（"银行补丁"）
   - TikTok / Spotify（证书固定，MITM 后白屏）
   - 支付宝 amdc（风控链路）
   - 12 家银行 + 政务

3. **`include_all_networks: false` / `include_apns: false`**
   > 我上一版误开了这两项，现已改回与旧版一致——全量抓取只会多耗电，对去广告没有帮助。

## 七、v9.9 的三个硬伤（建议改掉）

1. **4 个模块依赖已停更的上游**（小红书/微博/爱奇艺/滴滴 → `sooyaaabo/Egern`）→ 文件还在，但不会再更新。
2. **block_quic: false** → YouTube / TikTok / 大量广告 SDK 走 QUIC（UDP），完全绕过基于域名和 SNI 的规则。旧版只在 6 个策略组开了这个开关，那些组之外的 QUIC 流量不受管控。
3. **订阅 token 明文写在配置里** → 这就是它一直没能上传到公开仓库的原因。新版用占位符，配置本身可以公开托管、自动更新。

## 八、怎么选

- **想直接换**：用新版 `curated/Profile.yaml`，把订阅链接填进 `policy_groups → 订阅 → urls`。
- **想留在 v9.9**：至少做三件事——
  1. 把 4 个外链模块换成镜像内的更新版（小红书 `loonlab-plugin-79651793.lpx`、微博 `loonlab-plugin-ae197c04.lpx`、爱奇艺 `fmz200/partA/iQIYI.sgmodule`、滴滴 `loonlab-plugin-94431976.lpx`）
  2. `block_quic` 改 `true`
  3. 广告层加上 `curated/rules/ad-full.yaml`（+78,412 个域名），并在 `dns.forward` 第一条加 `proxy_rule_set → reject`
- **想混用**：新版只依赖镜像里已有的文件，`ad-full.yaml` / `cn-full.yaml` / `extra-*.yaml` 都可以单独拿去挂到 v9.9 上。

### 附：口径说明

- "广告域名覆盖"用**集合包含后缀继承**计算：`x.adsame.com` 被 `DOMAIN-SUFFIX,adsame.com` 覆盖算已覆盖。这是真实生效口径，比"字面条目数"准确。
- 外链判定：对每个 URL 实际发起请求看 HTTP 状态码（最初只查本地镜像路径，导致把 4 个可用外链误判成死链，已更正）。
- 下载量按镜像内实际文件字节数累加，不含外链。

## 九、v10.0 合并版（2026-10-24 追加）

按「不整份切换、只把亮点合进 v9.9」的思路做了一版，产出
`C://Users//admin//.dsh//bot//workspace//Egern-增强全能版-v10.0-合并版.yaml`（2,780 行）。

**保留了 v9.9 的全部结构**：38 个策略组（smart + priorities / fallback 混用）、246 条手写白名单、
221 条 MITM excludes、block_quic 收口（全局 false + 6 组开）、工具类模块全部启用。

**加进去的 6 项**：

| # | 变更 | 效果 |
|---|---|---|
| 1 | `modules` 最前插 `00-override.yaml` | 唯一能压住其他模块误拦的手段，必须排第一 |
| 2 | `dns.forward` 最前插 `ad-full → reject` | 广告域名解析即失败，不建 TCP |
| 3 | 广告层 5 个 rule_set 合并成 1 个 `ad-full` | 域名覆盖 290,419 → 356,559（+66,140），去掉 `rule.kelee.one` 外链依赖 |
| 4 | 补 APNs / Steam 中国区 / 5 个分类补充包 | 分流更全 |
| 5 | 4 个 sooyaaabo 外链模块换镜像内更新版 | 小红书 7→10 接口、微博 28→69 接口 |
| 6 | 补 `default_proxy_group` | 新节点自动归类 |

**过程中发现并修掉一个真问题**：DNS 层的 reject 是全局的，**不受 rules 顺序影响**。
v9.9 的 145 条白名单（`amdc.alipay.com`、`taobao.com`、抖音全链路…）即使排在广告规则之前，
DNS 层照样会把它们 reject 掉——支付宝风控、抖音播放都会中招。
所以生成 `ad-full` 时把这 145 个域名及其子域剔除了（2,019 条，占 0.53%），清单落在
`curated/rules/ad-exclude.txt`，可审计。

**校验**：38 组无重名 / 317 条规则引用全对 / 79 个模块（48 启用）+ 69 个规则集路径全命中 /
无重复 URL / 白名单零残留。

**回滚**：三条改动都是独立段落，注释里写了「回滚：删掉这 N 行，把 v9.9 的旧段落贴回来」。
